# rbac Specification

## ADDED Requirements

### Requirement: 班级切换仅对任教班级开放的教师可用
系统 SHALL 提供班级切换端点（页面表单路由），仅接受 role=teacher 的已认证用户；目标班级必须存在于该教师的任教关系（teacher_classes）中，否则拒绝；学生与非任教班级一律拒绝且不改变会话状态。

#### Scenario: 教师切换到任教班级成功
- **WHEN** 任教 A、B 两班的教师提交切换到 B 班的请求
- **THEN** 系统更新会话生效班级为 B 并重定向回仪表盘（展示 B 班列表）

#### Scenario: 教师切换到非任教班级被拒绝
- **WHEN** 仅任教 A 班的教师（通过构造请求）尝试切换到 C 班
- **THEN** 系统返回 403 Forbidden；会话生效班级保持不变（仍为 A）；不产生任何数据库写入

#### Scenario: 学生请求切换被拒绝
- **WHEN** 已认证的学生（页面无控件，但直接构造请求）提交班级切换
- **THEN** 系统返回 403 Forbidden；生效班级保持为其自身 class_id

#### Scenario: 未登录请求切换被拒绝
- **WHEN** 未携带有效会话的请求提交班级切换
- **THEN** 系统重定向到登录页（页面路由语义），不得执行任何切换逻辑

#### Scenario: 切换目标班级不存在被拒绝
- **WHEN** 教师提交切换到系统中根本不存在的 class_id
- **THEN** 系统返回 403（或 400）拒绝，生效班级不变，不自动创建班级

### Requirement: 任教关系数据由服务端维护
系统 SHALL 用服务端数据（teacher_classes 关系）作为教师可切换班级集合的唯一事实来源；任何客户端传入的班级参数不得绕过该关系校验。

#### Scenario: 客户端伪造任教关系无效
- **WHEN** 请求中携带任何声称"我有权访问某班"的参数或 Cookie 篡改
- **THEN** 服务端 SHALL 仅以数据库中 teacher_classes 记录为准进行校验，伪造值不产生任何效果

#### Scenario: 任教关系变化后切换范围立即收窄
- **WHEN** 教师的某条任教关系被移除后，该教师尝试切换到该班级
- **THEN** 系统 SHALL 拒绝（403）；已处于该生效班级的既有会话在下次校验或切换时按最新关系处理
